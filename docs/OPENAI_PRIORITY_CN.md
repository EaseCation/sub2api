# OpenAI 优先保障模式

管理员在「用户管理 → 创建 / 编辑用户」设置 **OpenAI 优先保障**。数据库字段为 `users.openai_priority`，默认 `false`，普通用户不能修改。修改后对该用户已有和新建的所有 API Key 生效，并主动失效鉴权缓存。

在「系统设置 → 网关 → OpenAI 优先保障模式」开启功能并单独保存。模式默认关闭，最低触发账号数量默认 **2**，允许配置为非负整数（0 表示仅在可用账号为零时触发）。

统计范围是全站 OpenAI 实体账号，不按分组分别触发，不把 Spark 等虚拟影子账号重复算作实体供给。仅统计正常调度账号：排除禁用、错误、暂停、已过期自动暂停、过载、限流、临时不可调度、API Key 配额耗尽及现有调度阈值/自动暂停规则判定不可用的账号。这里衡量账号池容量，不以某个模型支持情况或瞬时并发占满判定账号失效。

- 可用数量 **≤ 阈值**：仅 `openai_priority=true` 的用户可发起 OpenAI 请求，管理员身份本身不豁免。
- 可用数量 **> 阈值**，或管理员关闭功能：自动恢复普通用户的 OpenAI 请求。
- 优先保障不绕过余额、用户状态、分组权限、并发限制或上游实际可用性。
- 其他平台不受影响；合成分组按解析后的目标平台判断。
- 已开始的请求和流式输出正常完成；WebSocket 在下一轮请求开始前重新判断，不在当前轮中途断开。

被限制的新 HTTP 请求返回 `503`，错误码 `openai_priority_required`，带 `Retry-After: 5`。状态读取异常使用独立错误码 `openai_priority_unavailable`，不会把数据库异常误报为账号数为零。WebSocket 后续轮次被限制时使用 1013 关闭码，请客户端稍后重试。

全站网页在模式触发时显示警告，管理员、普通用户和未登录访客均可见；恢复后自动消失。网关状态缓存约 2 秒，网页每 5 秒检查一次（隐藏页面暂停检查，切回时刷新）。优先保障配置在本进程保存后立即使状态缓存失效，其他实例最多约 2 秒同步。公网状态接口仅返回是否触发，不公开账号清单或数量。

本次新增迁移 `242_user_openai_priority.sql`，随应用启动的正常数据库迁移执行；无需修改现有用户或重新生成 Key。本功能开发不自动发布或部署。
